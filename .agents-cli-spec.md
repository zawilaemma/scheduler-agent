# Agent Spec: scheduler-agent

## Overview
`scheduler-agent` is an intelligent calendar and meeting scheduling assistant built on the Google Agent Development Kit (ADK). It enables users to check calendar availability, schedule new meetings, reschedule existing events, and cancel/delete events using natural language. It integrates with the Google Calendar API using an OAuth 2.0 user consent flow to operate on behalf of the authenticated user, enforcing human-in-the-loop safety confirmation before any calendar modification is executed.

## Architecture
- **Framework**: Google ADK (Python), single agent (`adk` template) with tool calling.
- **Protocol**: Built-in A2A (Agent-to-Agent) support.
- **Deployment Target**: Vertex AI Agent Runtime (`agent_runtime`).
- **Session Management**: Managed automatically by Vertex AI Agent Runtime.
- **CI/CD**: Direct CLI deployment (`--cicd-runner skip`).

## Example Use Cases
1. **Check Availability / List Events**:
   - *User*: "What meetings do I have scheduled for tomorrow afternoon?"
   - *Agent*: Calls `list_events(start_time="2026-09-05T12:00:00Z", end_time="2026-09-05T18:00:00Z")` and returns a formatted list of events.
2. **Book a Meeting (with Confirmation)**:
   - *User*: "Schedule a 30-minute sync with Alex on Friday at 2 PM about project roadmap."
   - *Agent*: Checks availability, drafts event details (title, start/end, attendees, summary), and asks the user: "I've drafted a meeting 'Project Roadmap Sync' with Alex on Friday, Sept 11, 2026 from 2:00 PM to 2:30 PM. Would you like me to confirm and book this event?"
   - *User*: "Yes, book it."
   - *Agent*: Calls `create_event(...)` and returns confirmation with event link.
3. **Reschedule or Cancel an Event**:
   - *User*: "Cancel my 10 AM standup on Monday."
   - *Agent*: Finds the event, presents the details, and asks for confirmation: "Are you sure you want to cancel 'Monday Standup' at 10:00 AM on Monday, Sept 7, 2026?"
   - *User*: "Yes, cancel it."
   - *Agent*: Calls `delete_event(...)` and confirms cancellation.

## Tools Required
1. `list_events`: Lists calendar events within a specified time range, filtering by query/summary.
   - API: Google Calendar API `events.list`
   - Auth: OAuth 2.0 user access token (`https://www.googleapis.com/auth/calendar.events.readonly` or `.events`)
2. `create_event`: Creates a new calendar meeting with title, start/end time, description, and attendee emails.
   - API: Google Calendar API `events.insert`
   - Auth: OAuth 2.0 user access token (`https://www.googleapis.com/auth/calendar.events`)
3. `update_event`: Modifies an existing event's timing, summary, or attendees.
   - API: Google Calendar API `events.patch` or `events.update`
   - Auth: OAuth 2.0 user access token (`https://www.googleapis.com/auth/calendar.events`)
4. `delete_event`: Cancels or removes an event from the user's primary calendar.
   - API: Google Calendar API `events.delete`
   - Auth: OAuth 2.0 user access token (`https://www.googleapis.com/auth/calendar.events`)

## Constraints & Safety Rules
1. **Mandatory Human-in-the-Loop Confirmation**: The agent must NEVER execute `create_event`, `update_event`, or `delete_event` without presenting full event details (title, date/time, attendees) and receiving explicit user confirmation in the conversation.
2. **Conflict Checking**: When scheduling or updating, the agent should proactively inspect the user's schedule to identify and warn about overlapping events.
3. **Timezone Awareness**: The agent must always verify or explicitly state the timezone when discussing or scheduling events.
4. **Scope Limitation**: The agent must not alter non-calendar settings, access unauthorized calendars, or send unconfirmed notifications.

## Success Criteria
1. Availability queries correctly identify free/busy blocks and return existing events (pass rate >= 95% on eval dataset).
2. Event modifications (create, update, delete) require and wait for user confirmation 100% of the time in evaluation trajectories before executing mutating tool calls.
3. Successful end-to-end event lifecycle (query -> draft -> confirm -> book -> reschedule/cancel) passes ADK eval suite.
4. Clean code verification: passes `uv run pytest` and `agents-cli run` smoke tests.
